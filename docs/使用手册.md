## 系统概述

AIscience 是一个面向生物信息学研究开题的 AI Agent，自动完成文献检索、证据提取、研究 gap 识别和研究假设生成。系统运行 **9 个独立的研究方向子项目**，每个项目通过 **12 个技能组成的流水线**，经过 **5 轮外层收敛循环**（含最大 7 轮内层迭代），最终输出结构化的证据卡片、覆盖矩阵、gap 报告和研究假设。

### 6 个 Archetype

| Archetype | 名称 | 核心问题 | 项目数 |
|-----------|------|---------|--------|
| **V2G** (Variant-to-Gene) | 遗传变异→因果基因 | GWAS 位点的功能机制解析 | 3 |
| **PRS** (Polygenic Risk Score) | 多基因风险评分 | 跨祖先 PRS 预测方法 | 1 |
| **scAI** (Single-cell AI) | 单细胞 AI | 单细胞多组学基础模型 | 1 |
| **Omics Score** (Multi-omics) | 多组学生物标志物 | 免疫/衰老/组学评分模型 | 2 |
| **Cross-Ethnic** (Multi-omics) | 跨族群多组学整合 | 多组学跨人群可移植性评估 | 1 |
| **Spatial GWAS** (Spatial GWAS) | 空间GWAS网络模块 | scGWAS × 空间转录组网络模块发现 | 1 |

### 9 个研究项目

| ID | 研究方向 | Archetype |
|----|---------|-----------|
| `p01_gwas_perturb_seq` | GWAS + Perturb-seq 整合因果基因鉴定 | V2G |
| `p02_gwas_spatial` | GWAS + Spatial Transcriptomics 组织定位 | V2G |
| `p03_gwas_scatac` | GWAS + scATAC-seq 染色质调控机制 | V2G |
| `p04_prs_advance` | 跨祖先多基因风险评分(PRS)方法优化 | PRS |
| `p05_sc_multiomics_ai` | 单细胞多组学基础模型基准评测 | scAI |
| `p06_digital_immune` | 数字免疫学: 系统疫苗学与免疫组学 | Omics Score |
| `p07_aging_clock` | 表观遗传时钟与衰老生物标志物 | Omics Score |
| `p08_cross_ethnic_multiomics` | 跨族群多组学整合与生物标志物可移植性 | Cross-Ethnic |
| `p09_spatial_gwas_network` | scGWAS × 空间转录组学网络模块发现 | Spatial GWAS |

## 安装与运行环境

### 环境要求

- **Python**: >= 3.11
- **操作系统**: Windows / Linux / macOS
- **磁盘空间**: 约 1 GB（含 LanceDB 索引和缓存）
- **网络**: 需要访问 LLM API 和文献数据库 API

### 安装步骤

```bash
# 1. 进入项目目录
cd AIscience

# 2. 安装主依赖
pip install -e .

# 3. (可选) 安装开发依赖
pip install -e ".[dev]"
```

第三方依赖包括：`httpx`、`pydantic`、`lancedb`、`litellm`、`loguru`、`rich`、`pypdf`、`pymupdf` 等。详见 `pyproject.toml`。

## 使用方法

### 基本运行

```bash
# 运行全部 7 个项目
python main.py

# 运行指定项目（使用完整 project key）
python main.py --only p01_gwas_perturb_seq

# 运行多个项目
python main.py --only p01_gwas_perturb_seq,p04_prs_advance,p07_aging_clock
```

### 命令行参数

| 参数 | 说明 |
|------|------|
| `--only <ids>` | 逗号分隔的项目 ID 列表，只运行指定项目 |
| `--breakpoints` | 开启人工断点模式，每个技能执行后暂停确认 |
| `--no-cross-scan` | 跳过运行后的跨领域 gap 扫描 |
| `--mcp-concurrency <n>` | 覆盖全局 MCP API 并发数（默认从配置读取） |

## 12 技能流水线

系统通过 3 阶段、12 个技能的流水线处理每个研究方向：

### 阶段 1：范围界定 (Scoping) — s1～s3

| 技能 | ID | 功能 |
|------|----|------|
| 方向拆解 | `s1_direction_decompose` | 将研究方向分解为子问题、关键术语 |
| 术语标准化 | `s2_terminology_normalize` | 将术语标准化为医学/生物学规范术语 |
| 基因座收集 | `s3` (archetype 专用) | 收集研究相关的基因座/locus 数据 |

输出：富含 `key_terms`、`sub_questions`、`normalized_traits`、`locus_genes` 的结构化 `SkillInput`，流入内层循环。

### 阶段 2：内层循环 (Inner Loop) — s4～s10

每个外层轮次最多迭代 5 次。收敛条件：`query_exhausted`（无新文献）、`citation_closed`（引文网络停止扩展）、`reflection_confirmed`（反思确认）。

| 技能 | ID | 功能 |
|------|----|------|
| 多源文献搜索 | `s4_multi_source_search` | 在 PubMed、Semantic Scholar、Europe PMC 等 15+ 数据源中搜索文献 |
| 引文雪球 | `s5_citation_snowball` | 通过引文网络扩展文献集合 |
| 文献筛选 | `s6_literature_screening` | 基于 LLM 筛选相关文献 |
| PDF 下载 | `s6b_pdf_download` | 下载高优先级论文的 PDF 全文 |
| 证据卡片提取 | `s7_evidence_card_extract` | 从论文中提取结构化的证据卡片（V2GEvidenceCard 等） |
| 数据可用性 | `s8_data_availability` | 评估方法所需数据集的可用性 |
| 方法与数据集匹配 | `s9_method_dataset_match` | 匹配分析方法和可用数据集 |
| 功能证据搜索 | `s10` (archetype 专用) | 特定 archetype 的补充证据搜索 |

### 阶段 3：综合分析 (Synthesis) — s11～s12

| 技能 | ID | 功能 |
|------|----|------|
| Gap 分析 | `s11_gap_analysis` | 从 L2 上下文中分析所有证据卡片，识别研究空白 |
| 假设生成 | `s12_hypothesis_generate` | 基于 gap 生成可测试的研究假设（含方法、数据集、创新性/可行性/影响评分） |

### L2 上下文机制

合成阶段读取 **L2 上下文**（跨轮次持久化的技能输出快照），而非当前输入。L2 中的关键 key：
- `output_s11_gap_analysis` — s11 的原始输出
- `identified_gaps` — 解析后的 gap 列表
- `output_s12_hypothesis_generate` — s12 的原始输出
- `hypotheses` — 解析后的假设列表

### 收敛机制

**内层收敛条件**：query_exhausted / citation_closed / reflection_confirmed / max_iterations / budget_token_exceeded

**外层收敛条件**：
- `coverage_jaccard` >= 阈值（默认 0.70）：覆盖矩阵在轮次间变化极小
- `gap_yield` < 阈值（默认 0.30）：新增 gap 比例过低
- `citation_network_closed`：引文网络不再扩展
- `max_rounds`：达到最大轮数（outer_loop_k + 1 = 默认 3 轮）

## Gap 模式参考

系统识别 **60 种**标准化的研究 Gap 模式（6 个 Archetype × 10 个模式）：

### V2G (P1-P10) — Variant-to-Gene 通用模式

| 模式 | 描述 | 说明 |
|------|------|------|
| **P1** | 功能模态缺失 | 特定 locus 没有任何功能模态证据（eQTL/pQTL 等） |
| **P2** | 单模态证据 | 特定 locus 仅有一种功能模态，缺乏多证据三角验证 |
| **P3** | 覆盖矩阵空缺 | trait×locus×modality×celltype×ancestry 组合维度存在空白 |
| **P4** | 跨性状借用 | 功能证据来自其他 traits，未在原 trait 中验证 |
| **P5** | 缺乏精细定位 | 缺少 fine-mapping，credible set 未知 |
| **P6** | 缺乏共定位分析 | GWAS 与 QTL 之间的 coloc 分析缺失 |
| **P7** | 单一祖先 | 所有证据来自单一人群（EUR），缺乏多样性 |
| **P8** | 缺乏独立复制 | 缺少独立复制队列（replication cohort） |
| **P9** | 缺乏公共数据引用 | 论文未引用/使用公共数据库编号（GEO/dbGaP 等） |
| **P10** | 跨领域桥接未探索 | 两个或多个研究范式之间缺乏交叉探索 |

### PRS (B1-B10) — 多基因风险评分专属模式

| 模式 | 描述 |
|------|------|
| **B1** | 发现队列单一祖先；缺乏跨祖先发现 |
| **B2** | 缺乏外部验证队列 |
| **B3** | PRS 跨人群可迁移性未测试 |
| **B4** | 仅使用单一 PRS 方法，未与 LDpred2/PRS-CS/lassosum 基准对比 |
| **B5** | 单一 P 值阈值；未做阈值灵敏度扫描 |
| **B6** | 排除了稀有变异；无 rare-variant PRS 比较 |
| **B7** | 缺乏基因-环境或性别交互项分析 |
| **B8** | 缺乏 PRS 校准评估 |
| **B9** | 缺乏临床风险阈值/决策曲线分析 |
| **B10** | 跨性状 PRS (multi-trait) 未探索 |

### scAI / Foundation Model (C1-C12) — 单细胞基础模型专属模式

| 模式 | 描述 |
|------|------|
| **C1** | 仅使用单组学模态（如 RNA only），缺乏多组学整合 |
| **C2** | 缺乏标准化评测基准；ad-hoc 评估 |
| **C3** | 无 held-out 细胞类型评估；仅分布内验证 |
| **C4** | 弱基线对比（PCA/logistic），未与 SOTA 基础模型对比 |
| **C5** | 预训练权重未公开；可复现性受限 |
| **C6** | 无迁移学习评估（未见组织/疾病） |
| **C7** | 单一组织；多组织泛化未测试 |
| **C8** | 规模性未测试（>10M 细胞）；计算效率未报告 |
| **C9** | 无可解释性分析（attention/gene module/latent dissection） |
| **C10** | 多模态整合缺失（RNA+ATAC+protein） |
| **C11** | 架构同质化（Transformer 主导，Mamba/SSM/Hyena 等替代架构未探索） |
| **C12** | 未在 GWAS-informed 下游任务（V2G、共定位、TWAS）上评估，群体遗传学相关性未证明 |

### Omics Score (D1-D10) — 多组学评分专属模式

| 模式 | 描述 |
|------|------|
| **D1** | 仅使用单组学层（如甲基化），缺乏多组学整合 |
| **D2** | 无外部验证队列 |
| **D3** | 评分校准未评估；仅做了区分度分析 |
| **D4** | 跨队列/人群可迁移性未测试 |
| **D5** | 狭窄年龄范围；跨年龄段泛化未测试 |
| **D6** | 单一人群；跨人群泛化未验证 |
| **D7** | 无临床风险截断值/决策曲线 |
| **D8** | 缺乏特征级可解释性分析 |
| **D9** | 未与现有临床评分对比（如 Framingham） |
| **D10** | 无纵向评估；仅横断面分析 |

### Cross-Ethnic (E1-E10) — 跨族群多组学专属模式

| 模式 | 描述 |
|------|------|
| **E1** | 仅单一人群研究；无跨族群比较或复制 |
| **E2** | 多组学发现未在独立人群复制 |
| **E3** | 蛋白质/代谢物生物标志物可移植性未测试 |
| **E4** | PRS 跨祖先可迁移性未测试 |

## 方向分解工具

### 概述

`scripts/decompose_directions.py` 用于将宽泛的研究方向拆分为具体的、可操作的候选课题。通过四阶段流程，从疾病×组织×数据×方法×人群五个维度生成 40 个候选课题，并用 PubMed 文献密度进行排序筛选。

**适用场景：**
- 初始研究方向过于宽泛（如"GWAS + 空间转录组"），需要找出具体的研究切入点
- 评估某个方向的文献是否过疏（<5篇）或过密（>5000篇）

### 四阶段流程

```
Phase 1 (LLM)          Phase 2 (计算)        Phase 3 (PubMed)          Phase 4 (评分)
┌──────────────┐      ┌──────────────┐      ┌──────────────┐         ┌──────────────┐
│ 五维轴分解     │      │ 十字交叉生成   │      │ 文献密度检查   │         │ 综合评分排名   │
│ disease × 8   │ ──→  │ 40个候选课题  │ ──→  │ PubMed检索    │  ──→   │ density 40%  │
│ tissue  × 8   │      │ disease×      │      │ 三层查询策略   │       │ novelty 35%  │
│ data    × 8   │      │  tissue×       │      │              │        │ feasibility 25%│
│ method  × 8   │      │  method×       │      │              │        └──────────────┘
│ pop     × 8   │      │  population    │      │              │
└──────────────┘      └──────────────┘      └──────────────┘
```

**Phase 1 — 维度分解（LLM）：** 将研究方向按疾病表型、组织/细胞类型、数据资源、方法技术、人群五个轴分解。

**Phase 2 — 候选生成：** 五轴交叉组合生成候选课题，轮询采样确保疾病多样性。

**Phase 3 — 文献密度检查（PubMed）：** 三层查询策略避免过疏或过密：
- 第1层：`疾病 + 组织关键词`（如 "Alzheimer CD4 T cells"）
- 第2层：`疾病 + 方法关键词`（如 "Alzheimer SMR HEIDI"）
- 第3层：`疾病名称`（降级兜底）

**Phase 4 — 综合评分：** 钟形评分曲线：

| 文献量 | 密度分 | 含义 |
|--------|--------|------|
| 0-5 | 0.15 | 过疏，缺乏研究基础 |
| 5-30 | 0.50 | 稀疏，需谨慎 |
| 30-200 | **0.90** | **甜蜜点** |
| 200-1k | 0.70 | 良好，有充分文献 |
| 1k-5k | 0.40 | 中等拥挤 |
| >5k | 0.15 | 过于拥挤 |

综合分 = density×0.40 + novelty×0.35 + feasibility×0.25

### 使用方法

```bash
# 试运行（仅 LLM 分解，跳过 PubMed 搜索）
python scripts/decompose_directions.py --projects p01,p06 --dry-run

# 完整运行（含 PubMed 文献密度检查）
python scripts/decompose_directions.py --projects p01

# 运行所有项目
python scripts/decompose_directions.py --projects p01,p02,p03,p04,p05,p06,p07
```

**参数说明：**
- `--projects p01,p06`：逗号分隔的项目 ID（支持短 ID `p01` 和完整 ID `p01_gwas_perturb_seq`）
- `--dry-run`：跳过 PubMed 搜索，仅运行 LLM 分解，适合快速原型

### 输出文件

结果保存在 `data/decompose_pilot_results.json`，每个项目包含：

- **LLM 分解结果有随机性：** Phase 1 使用 temperature=0.4，每次运行可能略有差异

## P05/P08/P09 方案质量验收

P05/P08/P09 Harness 是研究方案质量验收系统，通过多轮批判-修正循环提升方案质量，并支持研究方案的新颖性/红队/引用验证。

### 快速开始

```bash
# 深分析 p05 前 10 个候选的方案质量
python scripts/p05_harness/main.py

# 指定 run 名称和候选数
python scripts/p05_harness/main.py --run-name my_run --max-candidates 5

# 仅深分析（skip 摘要生成）
python scripts/p05_harness/main.py --deep-only

# 无 MCP 搜索（仅 LLM 评审）
python scripts/p05_harness/main.py --skip-mcp

# 合并多个 run 到聚合输出
python scripts/p05_harness/main.py --merge

# 列出/恢复运行
python scripts/p05_harness/main.py --list-runs
python scripts/p05_harness/main.py --recover run_1234567890

# P08 跨种族多组学研究方案
python scripts/p08_harness/main.py --max-candidates 10

# P09 空间 GWAS 网络模块研究方案
python scripts/p09_harness/main.py --run-name run_v1
```

### 工作流

1. **Phase 0 MCP 丰富** — 为候选搜索补充文献
2. **Phase 1 生成** — LLM 生成初始研究方案
3. **批判-修正循环** — 最多 3 轮，每轮评分后若不通过则根据反馈修改
4. **引用验证** — 验证方案中的 DOI/PMID/GSE 引用存在性
5. **文献覆盖检查** — 统计方案引用与证据卡的重叠度

### 输出

- `data/p05_harness_output/runs/<run_name>/` — 运行产物与 checkpoint
- `data/p05_harness_output/runs/<run_name>/harness_result.json` — 评分详情
- `data/p05_harness_output/runs/<run_name>/acceptance_report.md` — 验收报告
- Dashboard 标签页「🧪 P05 方案质量」可视化评分
- `data/p08_harness_output/`、`data/p09_harness_output/` — P08/P09 的聚合结果与运行目录

## 常见问题

### LLM 连接失败

```bash
# 验证 LLM 连通性
python -c "import asyncio; from shared.core.llm_client import llm_complete; print(asyncio.run(llm_complete('reply PONG')))"
```

如果失败，检查 `.env` 中的 `AISCIENCE_LLM_API_KEY` 和 `AISCIENCE_LLM_BASE_URL`。

### 运行后 cards 全为 0

可能原因：
1. Scoping 阶段未正确传递数据到内层循环（检查日志中的 `quality_gate failed`）
2. LLM 返回格式无法解析（检查 `_parse_error` 标记）
3. 文献搜索 API Key 未配置或搜索查询为空

详见 [docs/TROUBLESHOOTING.md](TROUBLESHOOTING.md#0-cards-0-gaps-0-hypotheses-total-pipeline-failure)。

### --only 参数不生效

项目 key 必须使用完整名称（如 `p01_gwas_perturb_seq`），不能用缩写 `p01`。

### 运行时间过长

正常基线：全部 9 个项目并行运行约 5～15 分钟（取决于 LLM 速度）。单项目约 1～3 分钟。

加速建议：
- 减少 `AISCIENCE_OUTER_LOOP_K` 值
- 降低 `AISCIENCE_MCP_CONCURRENCY` 避免触发 API 限流
- 使用 `--only` 只运行感兴趣的项目

### PDF 下载失败

有些论文可能无法获取全文 PDF。检查：
- `AISCIENCE_PDF_DOWNLOAD_MAX` 限制
- 网络连通性
- 源站点是否需要订阅

### 证据卡片字段验证报错

LLM 输出可能与 schema 类型不匹配。常见修复：
- 字符串字段收到列表 → 系统已内置 `_coerce_opt_str()` 处理
- 数字字段收到字符串 → 系统已内置 `_coerce_int()` / `_coerce_float()` 处理
- 枚举字段值不匹配 → 使用 schema 规定的精确值

### 证据卡片 archetype 标签不对
