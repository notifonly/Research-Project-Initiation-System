# AI / 计算机论文深度精读与批判性分析 Skill

你正在执行一次 AI / 计算机学术论文的深度精读、数学溯源与批判性分析。最终产出一份结构化 Markdown 笔记。

精读层的原则是**严谨还原**，数学层的原则是**推导可追溯**，评估层的原则是**证据约束下敢下判断**。

不要把笔记写成论文摘要的扩写版，也不要机械地逐章复述。目标是写出这样的效果：**一个真正读懂了论文、核查过关键证据、理解其数学来源的人，在向另一个聪明人解释这篇论文。**

---

## 一、总原则

### 1. 事实、推断与评价必须分开

笔记中的内容应明确区分：

- **论文明确陈述的内容**：作者在正文、附录或补充材料中直接给出的事实、方法、结果与解释。
- **可由原文补全的推导**：原文省略部分步骤，但可以根据已给定义和标准数学规则严格补全。
- **合理推断**：原文没有明确说明，但可以根据上下文、实现方式或前驱工作推测。
- **外部证据**：来自公开评审、作者回复、代码仓库、后续论文或独立复现。
- **个人判断**：基于上述事实与证据作出的批判性评价。

合理推断、补充推导和个人判断必须明确标注，不得写成作者原话。

### 2. 判断强度必须与证据强度匹配

证据不足时，应使用：

- “论文尚未证明……”
- “现有实验仅部分支持……”
- “该结果还不能排除……”
- “目前无法确认……”

不能因为缺少证据便直接断言方法无效，也不能因为主表分数更高就接受作者的全部因果解释。

### 3. 严格区分信息状态

对于未获得的信息，使用以下准确表述：

- **原文未报告**：已经检查相关章节，但论文没有提供。
- **公开来源暂未找到**：当前检索没有发现，但不能断言不存在。
- **当前材料不足以确认**：已有内容无法支持确定结论。
- **不适用**：由论文类型决定，该项不构成合理要求。
- **确认不存在**：只有获得充分证据时才能使用。

不得把“没有搜到”写成“不存在”。

### 4. 关键主张必须可追溯

关键方法事实、数学公式、实验数字、版本变化、审稿意见和外部评价，应尽量标注：

- 章节与小节；
- 页码；
- 定义、定理、公式编号；
- 表号与图号；
- 附录位置；
- 对应来源 URL。

搜索结果摘要只能用于发现来源，不能作为关键结论的唯一证据。

# 前置准备

## 1. 确认论文身份

用户可能提供：

- arXiv ID，例如 `2301.00001`；
- arXiv 摘要页链接；
- PDF 直链；
- DOI；
- OpenReview、会议或出版方页面；
- 论文标题；
- 本地 PDF 或其他论文文件。

如果信息不足以唯一确定论文，应先检索并核对：

- 完整标题；
- 作者；
- 年份；
- 会议或期刊；
- arXiv ID 或 DOI；
- 是否存在同名或近似标题论文。

若仍存在多个合理候选，先向用户确认目标论文，不要自行选择。

## 2. 记录检索时间与阅读范围

在笔记元数据中记录：

- **正文阅读版本**；
- **外部信息检索截止日期**；
- 是否读取正文、附录和补充材料；
- 是否检查公开评审；
- 是否检查官方代码；
- 是否检查前驱与后续工作。

“后续影响”“代码状态”和“公开评审”会随时间变化，因此必须注明检索截止日期。

## 3. 获取论文元数据与全文

按以下顺序获取资料：

1. 论文官方页面、会议页面、期刊页面或 arXiv 元数据；
2. 论文正文；
3. 附录与补充材料；
4. 作者官方项目页、代码仓库、数据集、模型卡或数据卡；
5. 公开评审与作者回复；
6. 直接前驱、竞争路线与同期论文；
7. 后续论文、独立复现与可靠的技术分析。

如果存在 arXiv 版本，应记录：

- 当前阅读的是 v1、v2、v3 或其他版本；
- 各版本发布时间；
- 标题、方法、实验和结论是否变化；
- 主要版本差异；
- 当前分析基于哪个版本。

如果无法完整比较版本，应明确写“版本差异暂未完整核验”。

## 4. 来源优先级

证据可靠性从高到低大致为：

1. 论文正文、附录与补充材料；
2. 正式出版版本及作者官方版本；
3. 作者官方代码、配置、模型卡和数据卡；
4. 公开评审、作者回复与编辑决定；
5. 原始前驱论文和正式教材；
6. 后续学术论文及独立复现；
7. 高质量综述；
8. 博客、论坛和社区讨论。

低优先级来源可以帮助发现问题和理解背景，但不能单独支撑关键技术结论。

## 5. PDF 与 HTML 交叉核验

PDF 或 HTML 的自动抽取可能破坏：

- 双栏阅读顺序；
- 公式编号；
- 上下标与特殊符号；
- 表格结构；
- 图注；
- 脚注；
- 附录引用。

涉及关键公式、表格数字和算法步骤时，应尽量回到原始页面交叉核对。无法确认时，不得依赖损坏的抽取结果强行解释。

# 第一步：识别论文类型并裁剪分析框架

开始精读前，先判断论文主要属于哪种类型：

- 经验型方法论文；
- 理论论文；
- 系统论文；
- 数据集或 benchmark 论文；
- 应用论文；
- 综述或调查论文；
- 立场、观点或概念论文；
- 混合类型论文。

模板中的栏目不是为了强行填满。某项不适用时，应明确写“不适用”，而不是制造批评。

## 不同论文类型的重点

### 经验型方法论文

重点检查：

- 方法设计；
- 训练目标；
- baseline 公平性；
- 消融；
- 多次运行与统计可靠性；
- 效率和泛化；
- 替代解释。

### 理论论文

重点检查：

- 定义和问题设定；
- 定理的新颖性；
- 假设强弱；
- 证明完整性；
- 边界条件；
- 是否覆盖真实算法；
- 理论结果是否具有非平凡意义。

理论论文没有常规消融并不自动构成缺陷。

### 系统论文

重点检查：

- 硬件环境；
- 端到端延迟；
- 吞吐；
- 内存；
- 能耗和成本；
- 扩展性；
- 故障模型；
- 与强系统 baseline 的公平比较；
- 是否仅优化微基准而没有改善完整工作流。

### 数据集或 Benchmark 论文

重点检查：

- 数据来源和授权；
- 采样偏差；
- 标注流程与一致性；
- 数据泄漏与污染；
- 切分质量；
- 覆盖范围；
- 指标有效性；
- benchmark 是否容易被投机；
- 是否真的测量了声称的能力。

### 应用论文

重点检查：

- 场景是否真实；
- 评价是否对应实际价值；
- 部署约束；
- 风险与错误成本；
- 与领域专家或传统流程的比较；
- 外部有效性。

### 综述论文

重点检查：

- 文献覆盖；
- 检索与纳入标准；
- 分类框架；
- 是否遗漏关键路线；
- 是否公平描述争议；
- 是否把作者立场包装成领域共识。

### 立场或概念论文

重点检查：

- 核心命题是否清晰；
- 论证链是否完整；
- 证据是否支持主张；
- 是否忽略反例；
- 是否提出可证伪的预测或研究议程。

# 第二步：建立论文事实卡

在正式撰写叙事化笔记之前，先抽取事实，避免边读边补故事。

| 类别 | 需要抽取的信息 |
|---|---|
| 元数据 | 标题、作者、机构、年份、版本、会议或期刊 |
| 问题 | 论文试图解决的问题、输入、输出和应用场景 |
| 贡献主张 | 作者明确宣称的主要贡献 |
| 方法事实 | 核心模块、目标函数、算法流程、复杂度 |
| 数学基础 | 关键定义、公式、定理、假设和来源 |
| 实验事实 | 数据集、切分、baseline、指标、训练与计算预算 |
| 结果事实 | 主结果、方差、消融、效率、失败案例 |
| 外部证据 | 评审、作者回复、代码、复现、后续工作 |
| 暂缺信息 | 原文未报告或公开来源暂未找到的信息 |

事实卡服务于分析，不必原样出现在最终笔记中。

# 第三步：论文定位

## 1. 一句话定义

用一句话说明这篇论文本质上在做什么。

这句话不是摘要翻译，不罗列所有贡献，也不使用空洞评价。它应尽量包含：

- 解决的问题；
- 核心技术动作；
- 方法产生的主要价值。

## 2. 背景与动机

用两到四段解释：

- 论文出现时，这个方向处于什么阶段；
- 在它之前，研究者通常怎样处理该问题；
- 现有路线的核心局限是什么；
- 作者为什么认为值得重新处理；
- 论文是在解决真正的能力瓶颈，还是在优化某个 benchmark；
- 作者的问题定义是否合理。

必须区分领域背景事实和作者自己的叙事。不要默认作者声称的“现有方法不足”已经成立，应核对直接前驱。

---

# 第四步：核心方法精读

## 1. 方法概述

用自然语言还原完整信息流：

- 输入是什么；
- 输入怎样表示；
- 经过哪些关键处理；
- 各模块怎样交换信息；
- 训练阶段输出什么；
- 推理阶段输出什么；
- 与标准方案相比，新增、删除或替换了什么。

如果论文有架构图，不能只按图中方框逐项复述。应解释信息为什么按这个方向流动，以及哪个环节承担核心贡献。

## 2. 核心设计的直觉化翻译

对于每个核心模块、关键机制或重要设计，回答：

- 它实际上在做什么；
- 设计直觉是什么；
- 它解决了哪个具体问题；
- 没有它时可能出现什么；
- 作者为什么选择这种方案；
- 是否存在更简单的替代方案；
- 论文是否证明了该机制，而不只是展示整体方法有效。

若原文未解释选型理由，可给出推断，但必须标注：

> **我的推断**：……

不能把事后合理化写成作者的设计动机。

## 3. 公式推导与理论溯源

如果论文提出、修改或组合了数学公式，不要只翻译符号，还要尽可能还原它的数学来源、推导过程和设计边界。

优先分析：

- 核心训练目标；
- 模型更新规则；
- 概率模型；
- 作者宣称原创的表达式；
- 支撑理论结论的关键等式或不等式；
- 从理论形式转化到实际算法的公式；
- 相对前驱工作发生实质变化的公式。

普通符号定义、常规评价指标和无关紧要的展开不必逐一溯源。

### 3.1 公式在计算什么

对每个关键公式说明：

- 输入变量；
- 输出；
- 可学习参数；
- 优化变量；
- 求和、期望或积分范围；
- 该公式在算法中的调用位置；
- 它对训练或推理行为的实际影响。

不能停留在逐符号解释，必须说明整个表达式完成了什么数学操作。

### 3.2 判断公式来源类型

判断公式属于以下哪类：

1. 从本文前面的定义、假设或公式严格推出；
2. 从经典公式、定理、概率模型或优化目标变形而来；
3. 在前驱工作的公式上增加、删除或替换某些项；
4. 将多个已有目标或机制重新组合；
5. 理论推导与启发式设计的混合；
6. 完全由设计目标驱动的启发式公式；
7. 当前证据不足，无法确认来源。

### 3.3 建立内部与外部推导链

同时追踪两条链：

- **论文内部链**：当前公式由本文哪些定义、假设和前序公式得到；
- **论文外部链**：前序公式源自哪篇工作、哪个经典目标、定理或数学工具。

按照以下形式组织：

```text
基础定义或定理
→ 经典目标函数
→ 前驱论文的变形
→ 本文前序公式
→ 本文核心公式
→ 实际实现中的近似或离散形式
```

不得把论文引用的二手文献误写成公式最早来源。无法追到原始出处时，应写“目前只能确认至该来源”。

### 3.4 逐步还原推导

从最近的已知公式开始，展示必要的中间步骤。每一步说明使用了什么操作，例如：

- 代入定义；
- 代数展开；
- 取对数；
- 展开期望；
- 应用链式法则；
- 使用贝叶斯公式；
- 使用 Jensen 不等式；
- 变量替换；
- 重新参数化；
- 加入正则项；
- 省略与优化变量无关的常数；
- 使用一阶或高阶近似；
- 连续形式离散化；
- 用采样估计替代精确期望。

每个公式后必须跟一段人话解释，说明该数学变换如何改变方法行为。

### 3.5 列出成立前提

检查推导是否依赖：

- 独立同分布；
- 条件独立；
- 可微性；
- 凸性；
- 连续性；
- 可交换的期望与梯度；
- 特定分布形式；
- 归一化；
- 有限方差；
- 大样本极限；
- 边界条件；
- 平稳性；
- 模型表达能力；
- 其他未明确说明的假设。

若假设只在理论模型中成立、在实际实验中并不成立，应明确指出。

### 3.6 区分推导与设计选择

必须区分：

- 严格推导得到的项；
- 近似得到的项；
- 为计算可行性引入的项；
- 经验权重；
- 温度系数；
- 截断项；
- 正则项；
- 归一化方案；
- 损失项组合；
- 手工设置的边界或阈值。

不能把作者的建模选择包装成数学必然性。

### 3.7 对照来源公式

若公式源于已有工作，应说明：

- 原公式表达什么；
- 本文保留了什么；
- 新增了什么；
- 删除了什么；
- 替换了什么；
- 这些变化如何影响优化目标、梯度、计算量和归纳偏置；
- 在什么条件下本文公式会退化为来源公式。

### 3.8 检查推导可信度

重点检查：

- 等号是否实际应为近似号、比例号或上下界；
- 是否省略了会影响最优解的项；
- 推导方向是否成立；
- 是否混淆必要条件和充分条件；
- 期望、积分、极限和梯度的交换是否有条件；
- 概率分布是否正确归一化；
- 理论目标是否与代码实现一致；
- 定理分析是否只覆盖算法的简化版本；
- 公式行为是否与作者的文字解释一致；
- 极端取值或边界条件下是否出现异常。

发现缺口后，应判断它影响的是：

- 论文对方法的理论解释；
- 性能保证；
- 算法正确性；
- 还是只影响论证完整性。

### 3.9 原文缺少推导时的处理

明确区分：

- **论文明确给出的推导**；
- **根据论文定义可以严格补全的推导**；
- **基于前驱理论的合理推测**；
- **当前证据不足，无法确认的步骤**。

如果某一步无法严格推出，应直接指出推导在此发生跳跃，不得补入原文没有的假设。

### 3.10 关键公式的推荐写法

```markdown
#### 公式 X：公式名称或作用

**本文公式**

[公式]

这个公式负责……

**直接来源**

它直接来自本文公式（Y）/前驱工作的公式（Z）/某个经典定义。来源公式表达的是……

**推导过程**

[必要的中间公式]

第（1）步使用……；第（2）步依赖……；第（3）步省略了……。用人话说，这个过程把……变成了……

**本文的改动**

作者增加、删除或替换了……。其中……是严格推导结果，……是建模选择。

**成立条件与边界情况**

该公式依赖……。当……时，它退化为……；当……趋近于……时，可能发生……

**溯源结论**

该公式属于“经典公式的直接变形 / 前驱方法的扩展 / 理论加启发式项 / 完全启发式设计”。原文推导状态：完整 / 部分给出 / 未给出。
```

## 4. 训练细节

如果论文涉及训练，应还原：

- 数据来源与预处理；
- 数据规模和切分；
- 预训练与微调过程；
- 训练目标和各损失项；
- 优化器；
- 学习率与调度；
- batch size；
- 训练步数或 epoch；
- warm-up；
- gradient clipping；
- 权重衰减；
- 正则化；
- 随机种子；
- 混合精度；
- 硬件环境；
- 参数量；
- 训练成本；
- 关键超参数及选择方式。

只保留影响理解、复现和公平比较的细节，不机械抄写所有配置。

## 5. 推理与复杂度

分析：

- 时间复杂度；
- 空间复杂度；
- 序列长度、图规模或输入尺寸如何影响成本；
- 是否需要迭代推理、搜索、采样或额外模型；
- 推理延迟；
- 吞吐；
- 峰值内存；
- 测试时增强；
- 后处理；
- 硬件依赖。

不要只写渐近复杂度。应解释它在论文的实际规模下意味着什么，以及瓶颈从何时开始出现。

---

# 第五步：论文主张—证据审计

先列出论文最核心的主张，再逐项审查证据。不要按论文表格顺序被动复述。

| 核心主张 | 作者提供的证据 | 最强替代解释或反证 | 证据缺口 | 当前判断 |
|---|---|---|---|---|
| 主张 1 | 对应实验、定理或分析 | 其他可能解释 | 缺少哪些控制 | 充分支持/部分支持/尚未支持 |
| 主张 2 | 对应证据 | 其他可能解释 | 缺口 | 判断 |

对每项主张追问：

- 证据是否直接测量了该主张；
- 证据是否只证明相关性，没有证明因果机制；
- 是否存在一个不依赖核心方法、但同样能解释结果的因素；
- 是否需要额外实验才能排除替代解释；
- 作者的文字结论是否超出了证据范围。

常见替代解释包括：

- 更大模型；
- 更多训练数据；
- 更长训练时间；
- 更高调参预算；
- 更强预训练权重；
- 不同数据增强；
- 额外后处理；
- 测试时策略；
- 不同硬件或数值精度；
- benchmark 泄漏；
- 选择性报告。

---

# 第六步：实验分析

## 1. 实验设置

### 数据集

说明：

- 使用了哪些数据集；
- 是标准 benchmark、作者自建数据，还是私有数据；
- 数据规模和切分；
- 任务覆盖范围；
- 是否存在类别不平衡；
- 是否可能出现训练—测试泄漏；
- 数据是否代表真实部署场景；
- 是否只选择了对方法有利的数据集。

对于作者自建数据，应额外检查：

- 采样方式；
- 标注流程；
- 标注者资质；
- 标注一致性；
- 清洗规则；
- 授权、隐私和数据治理；
- 数据是否公开。

### Baseline

说明：

- 对比了哪些路线；
- baseline 是否是当时真正有竞争力的方法；
- 是否遗漏重要方法；
- baseline 结果来自作者复现还是原论文；
- 是否对所有方法采用相同设置。

公平性应核对：

- 训练数据和额外数据；
- 参数量；
- 预训练模型；
- 初始化；
- 输入尺寸；
- 训练步数；
- 计算预算；
- 调参预算；
- 数据增强；
- 测试时增强；
- 采样与搜索策略；
- 后处理；
- 硬件；
- batch size；
- 精度格式。

如果无法对齐，应明确写出：

> 该比较无法把性能差异完全归因于论文的核心方法。

### 评估指标

解释：

- 指标测量什么；
- 为什么适合该任务；
- 它忽略什么；
- 是否可能被投机；
- 是否与真实应用目标一致；
- 是否需要补充鲁棒性、校准性、公平性、效率或人工评价。

## 2. 核心结果

分析主要结果时，应说明：

- 提升的绝对值和相对值；
- 哪些数据集、规模和条件下提升最大；
- 哪些条件下提升有限或退化；
- 是否超过随机波动；
- 是否只在单一指标上成立；
- 精度提升是否以速度、内存、数据或训练成本为代价；
- 提升是否具有实际意义。

不要只抄表格，也不要把任何正数变化写成“显著提升”。除非论文完成统计显著性检验，否则“显著”只能表达幅度大，不能暗示统计意义。

## 3. 统计可信度

检查：

- 随机种子数量；
- 是否报告均值；
- 是否报告标准差、标准误或置信区间；
- 是否只报告最好的一次运行；
- 样本量；
- 多重比较风险；
- 是否反复使用测试集调参；
- 人工评价的评审者数量；
- 评审者一致性；
- 大模型评审是否依赖单一 judge；
- 误差条代表什么；
- 小幅提升是否落在正常波动范围内。

如果论文没有提供足够统计信息，应明确说明结论可以被支持到什么程度。

## 4. 消融实验

逐一分析每项消融：

- 它试图验证哪个设计；
- 只改变了一个变量，还是同时改变多个条件；
- 参数量和训练预算是否被控制；
- 被移除模块是否用合理替代项补齐；
- 结果是否真的支持作者声称的机制；
- 是否只是说明“完整模型比残缺模型好”；
- 是否缺失关键模块的消融；
- 是否缺少超参数敏感性分析；
- 是否只在一个数据集上做消融。

消融要围绕主张—证据关系分析，而不是按表格逐行复述。

## 5. 失败案例与适用边界

检查论文是否提供：

- 定性失败案例；
- 分布外结果；
- 长尾表现；
- 噪声鲁棒性；
- 不同规模下的趋势；
- 极端输入；
- 跨域泛化；
- 对抗或异常情况；
- 负面结果。

说明方法在哪些条件下有效，在哪些条件下会退化，以及论文是否诚实呈现这些边界。

## 6. 效率与成本

如果论文宣称高效，应核对：

- FLOPs 是否对应实际延迟；
- 吞吐和延迟是否在相同硬件上测量；
- batch size 是否一致；
- 峰值内存；
- 训练成本；
- 推理成本；
- 数据成本；
- 是否依赖额外模型、缓存、索引或预处理；
- 是否把离线成本排除在比较之外；
- 理论复杂度优势是否在实际规模中出现。

---

# 第七步：横向定位

## 1. 直接前驱

识别论文直接建立在哪些工作之上，并说明：

- 继承了什么；
- 修改了什么；
- 放弃了什么；
- 解决了前驱的哪个限制；
- 实际增量是概念性的、数学性的，还是工程性的。

## 2. 竞争路线

寻找处理同一问题的其他技术路线，比较：

- 核心假设；
- 数据需求；
- 计算成本；
- 可扩展性；
- 泛化；
- 可解释性；
- 工程复杂度；
- 适用场景。

不要默认论文选择的路线就是唯一合理路线。

## 3. 同期工作

检查同期是否出现相似工作。若有，比较：

- 问题定义；
- 发布时间；
- 方法差异；
- 实验设置；
- 结论；
- 是否存在独立发现；
- 哪条路线后来更有影响。

## 4. 公式谱系

对最关键的数学表达建立演化链：

- 最初来自哪个定义、理论或工作；
- 前驱论文怎样变形；
- 本文怎样进一步修改；
- 后续工作是否沿用或修正；
- 本文的数学贡献属于沿用、重新参数化、近似、增加正则项、组合目标，还是提出了真正的新结构。

## 5. 后续影响

如果论文已经发表一段时间，应检查：

- 是否有后续工作使用该方法；
- 是否成为常见 baseline；
- 是否有独立复现；
- 是否有工作修正其局限；
- 是否有结论被推翻或缩小；
- 实际影响来自方法、数据、问题设定、开源实现，还是传播效应。

引用数量不能直接等同于技术价值。

如果论文刚发表，应写“目前尚不足以判断长期影响”，不要虚构影响力。

---

# 第八步：批判性评估

这是证据约束下的强判断层。先摆事实，再给判断。

## 1. 可信度评估

### 实验公平性

判断：

- baseline 是否足够强；
- 数据、模型和预算是否对齐；
- 是否选择了有利的数据集或指标；
- 是否存在选择性报告；
- 是否报告不利结果；
- 是否存在污染或泄漏风险。

### 消融完整性

判断：

- 核心设计是否都有实验支撑；
- 消融是否控制变量；
- 是否缺少明显的简单替代方案；
- 是否把多个组件捆绑在一起验证；
- 作者的机制解释是否得到直接证据。

### 统计可靠性

判断：

- 结果是否稳定；
- 小幅提升是否可信；
- 是否报告足够种子；
- 是否存在测试集调参或多重比较问题；
- 人工评价是否可靠。

### 可复现性

检查：

- 代码是否公开；
- 仓库是否为作者官方仓库；
- 是否有许可证；
- 数据和预处理是否可获得；
- 关键超参数是否完整；
- 环境和依赖是否说明；
- 随机种子是否给出；
- 检查点是否提供；
- 计算资源是否现实；
- 代码是否与论文描述一致。

未找到代码时写：

> 截至外部信息检索截止日期，公开来源暂未找到作者官方代码。

不要直接写“代码未开源”，除非已经确认。

### 公开评审

如果存在公开评审，记录：

- 审稿人的核心质疑；
- 评分和信心分；
- 作者回应；
- 评审意见是否在回复后改变；
- 最终决定；
- 论文后续版本是否补上相关实验。

公开评审权重较高，但不是绝对真理。应独立判断审稿意见是否准确，以及作者回应是否真正解决问题。

## 2. 数学推导的可信度

评估：

- 公式是否由前提严格推出；
- 是否有未说明的跳步；
- 是否把近似写成等式；
- 是否遗漏关键条件；
- 经验项是否被包装成理论必然；
- 定理是否支持真实实现；
- 理论保证是否依赖不现实假设；
- 数学目标是否对应作者声称的语义；
- 公式在边界条件下是否合理；
- 源公式是否被准确引用和修改。

发现问题时，要说明其影响层级：

- 只影响解释；
- 削弱理论保证；
- 使实验结论无法归因；
- 或直接影响算法正确性。

## 3. 方法本身的问题

追问：

- 方法依赖哪些假设；
- 假设在真实场景是否成立；
- 方法对数据、算力、标注或先验有什么隐性依赖；
- 是否存在作者轻描淡写的局限；
- 强结果是否来自特殊设置；
- 是否缺少简单但强的对照；
- 方法是否只是把成本转移到其他阶段；
- 结果是否能推广到论文没有测试的场景。

## 4. 贡献评估

比较作者宣称的贡献和实际贡献：

- 是新的问题框架；
- 新的数学方法；
- 新的模型结构；
- 新的训练目标；
- 扎实的工程整合；
- 大规模实证；
- 新数据集；
- 新评价方法；
- 或只是已有组件的组合。

组合已有组件不等于没有价值，但应准确描述其贡献性质。

给出一句明确的总体判断，包括：

- 是否值得精读；
- 最值得学习的部分；
- 证据最薄弱的部分；
- 它在该方向上的真实位置。

## 5. 未解决的问题

列出真正由阅读产生的问题，包括：

- 作者没有意识到的问题；
- 作者知道但没有解决的问题；
- 实验无法回答的问题；
- 理论与实现之间的缺口；
- 可能推翻结论的关键实验；
- 论文打开的新研究方向。

每个问题应尽量说明为什么重要，以及什么证据可以回答它。

# 写作要求

## 精读层

使用自然叙事，不写成论文目录的机械复述。

推荐的逻辑是：

> 作者面对的困难是什么 → 现有方法为什么处理不好 → 作者采取了什么核心动作 → 这个动作在数学和算法上如何实现 → 实验是否支持这个解释。

每个核心概念第一次出现时，用人话解释。公式出现后必须解释其数学操作和方法含义。

## 评估层

允许使用：

- “我的判断是……”
- “我读完后的感受是……”
- “这组证据最多能支持……”
- “这里的问题不是效果差，而是无法归因……”
- “作者证明了结果，却没有证明自己给出的机制解释……”

每个判断必须有对应事实。语言可以明确，但不能为了尖锐而夸大证据。

## 叙事优先级

不同内容不应平均分配篇幅：

- 核心方法与关键公式详讲；
- 决定结论可信度的实验详讲；
- 常规训练配置压缩；
- 重复结果不逐表复述；
- 与核心主张无关的背景从简。

建议篇幅比例：

- 论文定位：约 10%；
- 核心方法与数学溯源：约 35%；
- 主张审计与实验：约 25%；
- 横向定位：约 10%；
- 批判性评估：约 20%。

该比例可根据论文类型调整。

## 禁止事项

禁止使用空洞套话，例如：

- “综上所述”；
- “值得注意的是”；
- “不难发现”；
- “该研究具有重要意义”；
- “本文仍存在一定局限性”。

禁止空洞形容词，例如：

- “创新性地”；
- “开创性地”；
- “大幅提升”；
- “显著优于”。

除非紧接着给出具体对象、幅度、证据和成立条件。

还必须避免：

- 将 Abstract 翻译一遍充当精读；
- 只解释公式符号，不解释公式行为；
- 把启发式选择写成严格推导；
- 把作者主张写成既定事实；
- 把相关性结果写成因果机制证明；
- 编造版本差异、审稿意见、代码状态或实验细节；
- 用博客代替原始数学来源；
- 为了填满模板制造“不适用”的批评。

# 输出前质检清单

## 身份与来源

- [ ] 是否唯一确认了目标论文？
- [ ] 是否记录正文阅读版本？
- [ ] 是否核对版本历史及主要差异？
- [ ] 是否记录外部信息检索截止日期？
- [ ] 是否检查正文、附录和补充材料？
- [ ] 是否区分原始来源与二手来源？
- [ ] 是否避免把搜索摘要当成关键证据？

## 论文定位与方法

- [ ] 一句话定义是否真正只有一个核心判断，而非摘要翻译？
- [ ] 是否说明了问题为什么值得解决？
- [ ] 是否根据论文类型调整分析重点？
- [ ] 是否用自然语言还原完整信息流？
- [ ] 是否解释核心设计的直觉及其解决的问题？
- [ ] 是否区分作者解释和个人推断？

## 公式与理论溯源

- [ ] 是否识别了承担核心作用的公式？
- [ ] 每个核心公式是否说明输入、输出和整体作用？
- [ ] 每个公式后是否有人话解释？
- [ ] 是否追溯论文内部的定义、假设和前序公式？
- [ ] 是否追溯至外部原始论文、定理或经典目标？
- [ ] 是否写出关键中间推导步骤？
- [ ] 是否解释每一步使用的数学规则？
- [ ] 是否列出推导成立的假设？
- [ ] 是否区分严格推导、近似和启发式设计？
- [ ] 是否检查等号、近似、上下界和省略项？
- [ ] 是否说明本文相对来源公式修改了什么？
- [ ] 是否检查理论公式与实际实现是否一致？
- [ ] 无法确认的来源是否标记为暂缺，而不是脑补？

## 主张与实验证据

- [ ] 是否先列出核心主张，再逐项匹配证据？
- [ ] 是否考虑每项核心结果的替代解释？
- [ ] 是否检查数据、模型规模、训练预算和调参预算？
- [ ] baseline 是否真正有竞争力？
- [ ] 是否检查遗漏的重要 baseline？
- [ ] 是否评估指标能否测量论文声称的能力？
- [ ] 是否给出提升的绝对值、实际意义和代价？
- [ ] 是否检查随机种子、方差、置信区间和样本量？
- [ ] 是否检查测试集调参和数据污染风险？
- [ ] 是否逐项分析消融，而非一笔带过？
- [ ] 消融是否控制了参数量和其他变量？
- [ ] 是否分析失败案例和适用边界？
- [ ] 是否核对效率比较的硬件与测量设置？

## 横向定位与外部证据

- [ ] 是否检查直接前驱？
- [ ] 是否寻找竞争路线和同期工作？
- [ ] 是否建立关键公式谱系？
- [ ] 是否检查后续复现、修正或反驳？
- [ ] 顶会或公开评审论文是否检查了评审和作者回复？
- [ ] 是否独立判断评审意见，而非机械接受？
- [ ] 是否检查官方代码、数据和复现条件？

## 批判性评估

- [ ] 每个判断是否有具体事实支持？
- [ ] 判断强度是否与证据强度一致？
- [ ] 是否区分“效果成立”和“机制解释成立”？
- [ ] 是否指出理论缺口影响解释、保证还是正确性？
- [ ] 是否准确区分方法贡献、实验贡献和工程贡献？
- [ ] 是否给出一句话总体判断？
- [ ] 是否提出真正未解决的问题及验证方式？
- [ ] 是否避免外交辞令、空洞形容词和论文摘要腔？
- [ ] 是否区分“原文未报告”“暂未找到”“不适用”和“确认不存在”？
- [ ] 是否确保所有不确定细节均未被编造？
